План решения проблем компании "Александрит"

# 1. Ключевые проблемы
    ## Критические (срочно решить):
    - Потеря заказов B2B-клиентов – заказы не доходят из MES API в CRM.
    - Долгий расчёт стоимости (до 30 мин) – блокирует работу MES.
    - Тормоза в MES – операторы не могут быстро получить список новых заказов.
    ## Важные (решить в течение 1–3 месяцев):
    - Нет прозрачности статусов заказов – клиенты не знают, где их заказ.
    - Ручное тестирование → релизы задерживаются на месяц.
    - Кэширование.
    ## Технические долги (решить в 3–6 месяцев):
    - Разделение MES API на два сервиса (расчёт стоимости + работа с заказами).
    - Нет отказоустойчивости (все сервисы и БД на single-инстансах).
    - Автоматизация CI/CD (сейчас деплой в prod вручную).

# 2. План действий
    ## Этап 1. Экстренные меры (первые 2 недели)
    Цель: Остановить потерю заказов и ускорить работу операторов.
    - Мониторинг RabbitMQ и MES:
        Развернуть Yandex Managed Service for Prometheus + Grafana для сбора метрик:
            Очередь сообщений (необработанные, dead letters).
            Нагрузка на MES (CPU, RAM, время ответа).
            Настроить алерты при откланении от SLA.
    - Оптимизация MES:
        Временно ограничить количество одновременных расчётов стоимости (rate limiting).
    - Репликация БД:
        Настроить Master-Slave для ShopDB и MES DB.
        Чтение – на реплики, запись – на мастер.

    ## Этап 2. Стабилизация (1–3 месяца)
    Цель: Устранить основные узкие места и начать масштабирование.
    - Трейсинг заказов (OpenTelemetry):
        Отслеживать путь заказа: Internet Shop → MES → CRM → Production.
        Выявлять "зависшие" заказы (например, те, что не перешли в MANUFACTURING_STARTED).
    - Добавить статус API_SUBMITTED:
        Когда MES принимает заказ через API, он отправляет статус в CRM.
        Позволяет отслеживать заказы B2B с момента создания.
    - Автоматизация тестирования:
        Автоматизация E2E-тестов.
        Добавить интеграционные тесты API (Postman/TestContainers).
    - Оптимизация MES:
        Кэширование списка заказов (Redis) – снизит нагрузку на БД.
        Проверить пул соединений к PostgreSQL – увеличить при необходимости.

    ## Этап 3. Масштабирование (3–6 месяцев)
    Цель: Подготовить систему к росту нагрузки.
    - Выделение сервиса расчёта стоимости:
        Создать MES Pricing Calculator (отдельный микросервис на C#).
        Горизонтально масштабировать под нагрузку.
    - CI/CD для production:
        Автоматизировать деплой через GitLab CI/CD.


# 3. Целевая архитектура через 6 месяцев

    Frontend: 
        Vue (магазин)
        React (MES)
    Backend:
        Order API (Java) – приём заказов.
        MES + MES API (C#) – работа операторов.
        MES Pricing Calculator (C#) – расчёт стоимости.

    Инфраструктура:
        БД: PostgreSQL с репликами.
        Кэш: Redis.
        Мониторинг: Yandex Managed Service for Prometheus + Grafana
        Трейсинг: OpenTelemetry + Jaeger.

# 4. Три главные инициативы на полгода

    Внедрить мониторинг и трейсинг
        Зачем? Без этого невозможно понять, где теряются заказы.
        Как? Prometheus для метрик, OpenTelemetry для трейсов.

    Разделить MES API на два сервиса
        Зачем? Сейчас расчёт стоимости блокирует работу операторов.
        Как? Вынести расчёты в MES Pricing Calculator с горизонтальным масштабированием.

    Автоматизировать тестирование и CI/CD

        Зачем? Сейчас релизы задерживаются на месяц из-за ручных проверок.
        Как? Автотесты E2E, GitLab CI/CD для автоматического деплоя.

# 5. Ресурсы и команда

    Нанять:
        1 DevOps – для настройки мониторинга и CI/CD.
        1 QA-автоматизатор – для написания тестов.

    Перераспределить:
        Тимлид сосредоточится на архитектуре (а не на менеджменте).
        Разработчик C# займётся выделением MES Calc Core.

## Этот план:

    Быстро останавливает критические проблемы (потеря заказов, тормоза MES).
    Постепенно улучшает архитектуру (мониторинг, трейсинг, микросервисы).
    Готовит систему к росту нагрузки (репликация БД, автоматизация).
